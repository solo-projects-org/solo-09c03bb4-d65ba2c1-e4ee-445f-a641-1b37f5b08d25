# 地铁站间客流（闸机补传）

把闸机补传记录整理为按日的站间客流与待核清单。FastAPI + SQLite，单容器即可运行。

## 规则实现

* **解析**：CSV 表头 `事件号, 匿名卡号, 时刻, 站点, 方向, 修订号`（也接受英文
  `event_no, card_id, tap_time, station, direction, revision`，方向可写 `进站/出站` 或 `in/out`）。
  时刻按 UTC 解析；一次上传必须落在**连续两个 UTC 日**内，超出直接拒绝（HTTP 400）。
* **修订**：同一 `事件号` 更高 `修订号` 覆盖旧记录。文件内同一事件号只取最高修订；
  与库内已有 (事件号, 修订号) 且内容不同会被拒绝，提示改用更高修订号。
  更低修订号记为“忽略”，不会回退已有数据。
* **配对**：按卡号与时刻排序，相邻的 *进站 → 出站* 组成一段行程；跨午夜行程
  **计入进站日**。孤立刷卡、连续同向刷卡进入“待核”清单，不参与客流统计。
* **日状态**：每个 UTC 服务日有 `current`（现行）或 `stale`（待重算）两种只读状态。
  页面只展示 `current` 的站间人数与待核记录；`stale` 只显示过期提示与重算按钮。

## 一致性 / 过期语义

| 事件 | 行为 |
| --- | --- |
| 上传受理 | 同一事务内：写批次、写事件、把**所有受影响日期**标为 `stale`、入队重算任务。受理返回时旧结果已不可展示。 |
| 受影响日期 | 该卡所有事件的日期（新增/更正会改变整条刷卡序列的配对），必然同时包含跨午夜行程的两端日期。 |
| 重算成功 | 一个事务内替换结果、替换待核记录、把任务覆盖的**全部日期**一起置为 `current`；跨午夜配对的两端日期永远同事务发布，不会一半新一半旧。 |
| 重算失败 | 日期保持 `stale` 并记录错误；不发布任何部分结果。非临时错误直接标记任务失败。 |
| 服务重启 | 启动时 `recover()`：把中断的 `running` 任务重新排队；把 epoch 落后却声称 `current` 的日期降级为 `stale` 并删掉其可展示结果；为无任务的 `stale` 日期补建任务；随后清空队列。 |
| 并发上传 | 每个日期有单调递增 `epoch`。重算在快照中记录 epoch，发布前在写锁内重新校验；期间有新上传导致 epoch 变化，则放弃本次发布并重试。慢重算无法覆盖新修订。 |

## 启动

### Docker Compose（推荐，浏览器入口）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

数据持久化在命名卷 `ridership-data` 的 `/data/taps.sqlite3`；`docker compose down` 不会删除数据，
需要清空时用 `docker compose down -v`。健康检查走 `/healthz`。

### 本地

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --port 8000
```

环境变量：`TAPS_DB`（SQLite 路径，默认 `./data/taps.sqlite3`）、`DISPLAY_TZ`（仅影响页面时区标注，统计始终按 UTC 日）。

## 页面与接口

* `/`：上传、按日切换查看站间人数与待核记录、批次与重算任务列表。
* `GET /api/days`、`GET /api/days/{date}`、`GET /api/overview`
* `POST /api/uploads`（multipart 字段 `file`）：受理后立即尝试重算，返回受影响日期及状态。
* `POST /api/recompute?days=YYYY-MM-DD&days=...`：手动重算（用于失败后的修复）。

`/docs` 有 OpenAPI 交互文档。

## 已知限制

* **单实例部署**：SQLite + WAL 适合单节点。Dockerfile 固定 `--workers 1`；不要用多个副本
  同时挂载同一数据卷。
* **重算为同步触发**：上传受理后在同一请求内尝试重算（本地整库重算，量级在数万条内足够快）。
  重算失败时该日停留在“待重算”，页面提供重算按钮，或重启服务自动补排队；失败任务最多重试
  `MAX_JOB_ATTEMPTS` 次后标记为 `failed`，不会无限重试。
* **重复上传幂等**：若文件内容与库内完全一致（无新事件），不会把日期标为过期，只记一条空批次。
* 页面对 `stale` 日期不展示旧数字，只显示过期提示与错误原因；历史批次与任务仍可审计。
